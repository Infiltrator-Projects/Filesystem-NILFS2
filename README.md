# Filesystem-NILFS2

Native Common V2 recognition and bounded offline reader development. The reader implements committed super-root bootstrap, physical DAT mapping, virtual block lifetime validation, persistent allocator bitmap/counter checks, checkpoint ifile lookup, segment usage and direct/B-tree mappings. Initial mount profile requires identical clean committed anchors on both superblocks and the baseline 4096-byte/128-byte inode/32-byte DAT/192-byte checkpoint/16-byte segment usage sizes. No replay, snapshot selection, cleaning, writes, defragmentation or physical BOOT/kernel qualification is claimed. Exact-revision independent namespace and populated payload tests are required before runtime publication. The published v0.0.1 package remains documentation-only.

The CI populated-media gate now requires an independently created, cleanly unmounted NILFS2 image, with a multi-block random file, nested file and sparse file. The reference driver is exclusively a test-image producer; the Common V2 module uses only raw host I/O and must reproduce the exported bytes without changing the image. Missing reference-driver support is a qualification failure, not a skipped pass.
